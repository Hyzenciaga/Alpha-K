# Phase 1 Backend Contract

## Scope

This branch owns the Phase 1 backend foundation:

- `src/main/**`
- `src/shared/domain/**`
- `src/shared/ipc/**`
- database migrations and repositories
- backend unit and integration tests

Renderer implementation remains out of scope until the frontend and backend first versions are ready for IPC integration.

## Decisions

- One active Vault in Phase 1; schemas retain `vaultId` for future multi-Vault support.
- IDs are UUIDs generated by the host application.
- Persisted timestamps are UTC ISO 8601 strings.
- Vault-owned paths stored in SQLite are relative to the Vault root unless explicitly named `realPath`.
- `.knowledge-vault.json` has a versioned, strict schema.
- Accepting an inbox item changes logical state in Phase 1; large files are not moved automatically.
- Job Queue state is limited to `scheduled`, `queued`, `running`, `succeeded`, `failed`, `interrupted`, and `cancelled`.
- Workflow states such as validation or human review do not belong to the generic Job Queue state machine.
- Job claims use an immediate SQLite transaction, a worker ID, heartbeat, and lease expiry.
- A non-null `(type, idempotencyKey)` identifies one logical Job.
- Renderer-facing data crosses typed IPC as validated DTOs; repositories never leak SQLite row shapes.
- Rebuildable search metadata is read from `library/**/metadata.json` with schema version `1` and the
  required fields `id` and `title`; `summary`, `authors`, and `labels` feed the FTS index.

## Phase 1 Vertical Slice

```text
select or initialize Vault
→ persist active Vault
→ enqueue Job
→ claim with lease
→ heartbeat
→ complete or fail
→ restart
→ recover expired running Jobs
```

## Rebuild Boundary

Deleting SQLite can rebuild knowledge metadata and search indexes from Vault files. It cannot reconstruct transient Job history, leases, provider runs, or UI preferences.

## Renderer-facing API

The preload bridge exposes an additive Phase 1 API while keeping Node.js unavailable to the Renderer:

- `getVault()`
- `selectVault()`
- `rebuildVaultIndex()`
- `listJobs(filter?)`
- `cancelJob(jobId)`
- `retryJob(jobId)`
- `onAppEvent(listener)`

Every request returns an `IpcResult<T>` envelope. Main validates request DTOs and maps expected failures to stable error codes.
